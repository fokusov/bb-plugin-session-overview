# Контракт паспорта 1С для дашборда

## Почему текущего SDK недостаточно

В Plugin SDK 0.6.157 `projects.files` возвращает список `{name, path}` с признаком `truncated`, но не размеры. `projects.fileContent` возвращает весь `content` и `sizeBytes`; вход содержит `projectId`, `path` и необязательный `environmentId` или `hostId`, но не лимит байтов и не source id. Поэтому вызов не обеспечивает bounded read и точную привязку к выбранному каноническому source. Точный `bb--git.workspaceStatus` уже подходит для ветки и числа изменённых файлов, но не возвращает размеры.

RPC `1c-properties.state` распознаёт маркеры исходников и наличие `Configuration.xml`, но не выдаёт паспорт или метрики исходников. Не следует обходить ограничения новым произвольным файловым RPC в dashboard.

## Предлагаемый read-only контракт `1c-properties`

Метод `passport` получает `{ projectId: string, environmentId?: string }`. Произвольный путь от UI запрещён. `1c-properties` разрешает `projectId` в зарегистрированный проект, выбирает default source; если передан `environmentId`, проверяет его принадлежность этому проекту и использует его точную рабочую копию. В ответе возвращает snapshot time, выбранный source id, формат, список обнаруженных конфигураций и метрики.

Для XML паспорт читается из `Configuration.xml`; для EDT — из `src/Configuration/Configuration.mdo`. Для каждого найденного корня нужны техническое имя, синоним и версия, только если они реально присутствуют. Несколько конфигураций возвращаются отдельными строками. При нескольких потенциальных roots без однозначного выбора возвращается явная неоднозначность, а не произвольный результат.

Метрики объёма считают только tracked-файлы выбранного source; `.git`, кэши, тестовые базы, сборки и бинарные артефакты исключаются. Нужны размеры по расширениям и строки BSL. Ответ содержит `complete`, счётчики и причину неполноты. Ошибка чтения или превышение лимита не превращается в нулевые значения. Перед реализацией владелец `1c-properties` должен зафиксировать и проверить лимиты файлов, суммарных байтов и XML-файла на характерных проектах.

Обязательные проверки будущей реализации: два source одного BB-проекта и два worktree; XML и EDT; несколько конфигураций; отсутствие Git; tracked/untracked; symlink/junction за пределами корня; отсутствующий/слишком большой XML; исчерпание лимита и неполный snapshot. Для каждой метрики результат сверяется с независимым чтением на тестовых fixture.
