# Проекты и сессия

Опциональный плагин BB с дашбордом разработчика 1С и панелями треда.

Главный вид страницы «Проекты 1С» — календарь интенсивности за последние 12 месяцев или выбранный год и лента работы по месяцам и проектам. Календарь и лента используют один фильтр: метрика, проект и день в часовом поясе интерфейса. Доступны метрики «Треды», «Коммиты», «Задачи», «Сборки» и «Тесты». Охват источников и неполнота истории показаны явно. Ранние события ленты подгружаются страницами по три месяца. Метрики ходов, ревью и токенов не выводятся без контракта с отметкой времени. [Источники и правила](docs/1c-dashboard.md)

Карточки показывают имя проекта, активность за 30 дней, закрепление, поиск, сортировку по активности, блокерам и расходу, а также переключатель всех проектов. В деталях: рабочие копии и выбор worktree, Git-ветка и число изменённых файлов через опубликованный RPC `bb--git.workspaceStatus`, паспорт `1c-properties.passport` (XML/EDT, имя, синоним, версия, tracked-файлы и объём по расширениям), сводка OpenSpec и BSL Flow, задачи BB Tasks, журнал операций `1c-properties.platformDashboardV1`, расход и треды. Список тредов повторяет вложенность `parentThreadId`; строка открывает тред штатной навигацией BB. Выбранные период, метрика, проект, день и закрепления сохраняются при возврате из треда.

Расход загружается по явному действию для одного проекта: читаются только видимые треды (до 250) и типизированные события `thread/tokenUsage/updated` и `thread/contextWindowUsage/updated`. Сумма — сумма последних накопительных снимков, по одному на тред, включая дочерние. Тред учитывается в одной задаче; расход без задачи остаётся отдельной строкой; покрытие отделяет отсутствующие и неудачные чтения. Фактическая стоимость показывается только при наличии данных провайдера, расчётные тарифы не подставляются.

Качество связывается с ревизией: свежесть отчёта проверяется по окну семь дней и текущей ревизии исходников, для тестов показываются профиль, счётчики и дельта к предыдущему сопоставимому прогону, расхождение загруженной в базу ревизии с исходниками выводится отдельно.

## Границы

Используется штатный `navPanel` Plugin SDK 0.6.157 и панели треда. BB Core уже предоставляет навигацию, список проектов, тредов и окружений, поэтому отдельная инфраструктура не нужна. Git status берётся из опубликованного контракта `bb--git`, коммиты — из `git-history`, задачи — из `tasks`, OpenSpec — из `openspec-bsl-flow`. Плагин не изменяет проекты, базы, задачи и настройки; все контракты read-only.

В SDK 0.6.157 нет отдельного Tasks API, признака архива проекта, строк BSL и объектов метаданных в паспорте. Плагин не подменяет отсутствующие значения нулями и не обходит ограничения произвольным файловым RPC.

## Проверка

`npm run check` запускает TypeScript и fixture-тесты дашборда, панели треда, Git RPC и паспорта.

`npm run build` требует установленного BB CLI (`bb plugin build .`).
